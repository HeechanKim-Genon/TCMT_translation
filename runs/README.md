# runs/ — 실제 실행 기록

2026-08-03 야간 실행(22:17 → 01:14) 산출물 전체. **모델 응답 원문이 그대로 들어있다.**

용어 **100개** / **1,000개** 두 규모를 순차로 돌렸다. 두 경우 모두 매칭·번역에 쓴 사전은
최종번역사전 전체(표제어 54,861)다. 규모는 *평가 대상 용어를 몇 개 뽑았는지*를 뜻한다.

> 채점 근거를 추적하려면 정답이 필요하기 때문이다. 1,000행 규모의 사전 추출본에 해당한다.

## 입력 데이터 (`dataset_*/`)

| 파일 | 내용 |
|---|---|
| `terms.json` | 평가 용어. 영문 표제어 · 대표 한글명(`rep`) · **정답 집합**(`answers`) · KCD · 코드 보유 · 용어 유형 · 어절 수 |
| `sentences.json` | (b)용 캐리어 문장. 용어 유형에 맞는 템플릿에 용어를 끼운 것 (API 호출 없음) |
| `paragraphs.json` | (c)용 문단. Qwen 이 생성하고 검증 4종을 통과한 것 + 심어둔 용어 + 매칭 결과 |
| `meta.json` | 사용한 사전 경로와 실행 인자 (재현용) |

`answers` = 같은 **개념코드**를 공유하는 모든 한글명. 대표어만이 아니라 동의어까지 정답으로 인정한다.

## 결과 (`results_*/`)

### (a) 단어 단위 — `a_word_*`

| 파일 | 내용 |
|---|---|
| `a_word_1c.json` | 단어 1개 = 호출 1개 (기준선) |
| `a_word_1a.json` | 사전순 인접 50개를 한 번에 |
| `a_word_1b.json` | 무작위 50개를 한 번에 |
| `a_word_2A.json` | 도메인 힌트(`NOTE:`) 한 줄 추가 |
| `a_word_2C.json` | 정답 1개 + 오답 4개를 주고 택일 ← **사전 참조 arm** |
| `a_word_rows.csv` | 위 5개를 한 장으로 (엑셀 확인용) |
| `a_word_summary.json` | arm별 집계 + 사용량 + 응답 교차 기록 |

레코드 필드:

| 필드 | 뜻 |
|---|---|
| `raw` | **모델 응답 원문** (파싱 전 문자열) |
| `pred` | `raw` 에서 뽑아낸 한글 용어 |
| `grade` | `정답(대표)` / `정답(동의어)` / `오답` / `형식실패` |
| `level` | 어느 수준에서 맞았는지 — `exact` / `nospace`(공백무시) / `josa`(조사 제거) |
| `issues` | 형식 문제 목록 (`empty`·`multiline`·`bad_chars`·`missing_row`·`off_list` 등) |
| `finish` | API `finish_reason`. `length` 면 잘린 것 |

### (b) 문장 단위 — `b_sent_*`

`b_sent_none.json` / `b_sent_term.json` / `b_sent_random.json` — mode 별로 한 파일.

| 필드 | 뜻 |
|---|---|
| `sentence` | 번역시킨 영어 문장 |
| `raw` | **모델 응답 원문** (`KO:` / `TERM:` 2필드 그대로) |
| `ko` | 문장 전체 번역 |
| `term` | 모델이 `ko` 에서 잘라낸 용어 부분 |
| `glossary_given` | 프롬프트에 실제로 들어간 `GLOSSARY:` 줄 |
| `decoy` | (`random`) 일부러 준 틀린 한글명 |
| `followed_decoy` | (`random`) 그 틀린 값을 따라 썼는가 ← **인과성 근거** |

`term` 이 `ko` 의 부분문자열인지 코드로 검증한다(`issues` 의 `span_not_substring`).
그래야 "추출 실패"와 "번역 오답"이 섞이지 않는다.

### (c) 문단 단위 — `c_para_*`

| 파일 | 내용 |
|---|---|
| `c_para_none.json` · `c_para_term.json` · `c_para_random.json` | mode 별 결과. `terms`(용어별 판정) + `translations`(번역문) 두 묶음 |
| `c_para_terms.csv` | 용어별 Term% 판정 전건 |
| `c_para_translations.csv` | **영어 원문 + 한국어 번역문 전문** (2.9M) |
| `c_para_summary.json` | mode별 집계 + 매칭 재현율 + 응답 교차 기록 |

`translations` 레코드:

| 필드 | 뜻 |
|---|---|
| `src` | 번역시킨 영어 문단 |
| `ko` | 한국어 번역문 (NFKC 정규화 + 앞뒤 공백 제거만 적용) |
| `injected` | 프롬프트 용어집에 실제로 들어간 표제어 목록 |
| `n_injected` | 그 개수 |
| `crossed_suspect` | 응답 교차 의심 표시 (아래 참고) |

`terms` 레코드:

| 필드 | 뜻 |
|---|---|
| `matched` | 매칭기가 이 용어를 문단에서 찾아냈는가 |
| `injected` | 용어집에 들어갔는가 |
| `term_hit` | 표준 한글명이 번역문에 나타났는가 ← **Term% 의 판정** |
| `hit_form` | 어느 형태로 맞았는지 |

> **채점 대상은 문단에 심어둔 용어뿐이다.** 매칭에는 사전 전체가 걸리므로 용어집에는
> 심지 않은 표제어도 함께 주입되지만(`n_injected` 참고), 그것들은 채점하지 않는다.
> 자연 등장한 용어는 문맥에 따라 표준 한글명이 정답이 아닐 수 있기 때문이다
> (`mass` 가 종괴인지 질량인지는 문서마다 다르다).

## 결과를 해석하기 전에 볼 것 — `crossing`

각 `*_summary.json` 에 `crossing` 필드가 있다. 서빙이 다른 요청의 응답을 돌려주는
현상(응답 교차)의 탐지·복구·미해결 건수다. 자세한 설명은 저장소 루트 README 참고.

이번 실행 실측:

| 규모 · 단계 | 탐지 | 복구 | 미해결 |
|---|---|---|---|
| 1000 · 단어 (3,124호출) | 10 | 7 | 3 |
| 1000 · 문장 (3,002호출) | 2 | 2 | 0 |
| 1000 · 문단 (1,369호출) | 102 | 11 | **91** |
| 100 · 문장 (301호출) | 1 | 1 | 0 |
| 100 · 단어 / 문단 | 0 | 0 | 0 |

문단의 91건은 **탐지기 오탐**이다. 89건이 `random` 모드인데, 거기서는 모델이 오답을
따라가므로 자기 정답이 안 나오는 게 정상이라 판정이 헐렁하게 걸렸다. 의심 문단과 정상
문단의 Term% 가 3.4% vs 4.3% 로 차이가 없는 것이 근거다. **정작 중요한 `term` 모드는
의심 0건이다.** 판정 기준은 이 실행 이후 수정했으므로 다시 돌리면 이 숫자는 줄어든다.

## 알려진 한계

- **문단 결과에 `raw` 필드가 없다.** 문단 번역은 응답 전체가 번역문이라 파싱할 게 없어서
  `ko` 에 정규화만 적용해 넣었다. 실질적으로 원문과 같지만 엄격히는 원문 그대로가 아니다.
- **`random` 의 Term% 숫자는 쓰면 안 된다.** 오답을 채점 대상 용어들의 한글명 풀에서
  뽑는 탓에, 어떤 용어의 오답으로 같은 문단 다른 대상 용어의 정답이 배정되는 경우가 있다.
  모델이 그 오답을 충실히 따라 쓰면 정답으로 집계된다. 100규모에서 `random`(29.3%)이
  `none`(16.7%)보다 높게 나온 이유다. **오답 추종률은 이 결함과 무관하며 유효하다.**
- 문단은 사전 용어로 만든 **합성 데이터**다. 실제 진단서·소견서가 아니다.
